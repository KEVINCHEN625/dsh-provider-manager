# 旧 Provider 插件替代与卸载门槛

状态：2026-09-21 用户已给予条件授权：自研方案完成后测试，确认兼容使用再卸载之前安装的 provider 插件，使用自研方案。达到本文件验收条件后，不因卸载动作本身重复请求授权；未达条件不卸载。

## 当前结论：尚不满足卸载条件

0.1.1 是配置和凭据管理扩展，未注册 OpenCode Go 或 Command Code 的模型执行适配器。`src/host/providers.ts` 消费 `llm.listProviders/listModels`；bundle 仅挂管理插件。旧插件目前承担模型调用，不能以 54 项管理测试、目录读取或通用 mock headless 测试通过代替独立运行验收。

尚未完成：自研套餐执行适配层；三个套餐的真实端到端兼容测试；停用旧插件后的 Web/headless 验证；Muse Code 服务身份、官方 CLI 安装登录及订阅接入。不得把说明卡当作已接通的 provider。

## 候选范围

| 包 | 当前作用 | 卸载前必须满足 |
| --- | --- | --- |
| `dsh-llm-opencode-go` | OpenCode Go 执行、混合协议、模型配置和额度界面 | 调用与必要能力已迁移；原 route/model ID、凭据引用和历史配置可用 |
| `@mars-sea/dsh-commandcode-provider` | Command Code 调用、账户、套餐模型目录及相关控制 | GOAT 实際用法、所用模型协议、认证来源、账户选择及必要功能已覆盖 |
| `dsh-llm-providers-ui` | 第三方 provider 页面与共享卡片容器 | 自研页面已覆盖所需功能，且没有剩余插件依赖该容器 |
| `@opencode2dsh/dsh-plugin` | 另一路 OpenCode 集成 | 先核实它暴露的 route、模型与使用记录；只有功能已替代或确认为本次替代范围内不再需要，才能卸载 |

Web 与 headless 分别盘点、迁移和验证；它们当前依赖版本不同。dsh 自带 `llm-pi-ai`、settings、credentials、连接和其他基础服务不在第三方 provider 清理范围内。不得顺带清理无关插件、会话或凭据。

## 验收顺序

1. 逐 provider 建能力矩阵并补自研执行层；独立规划/审核，所有代码仍在 dsh 源码仓库外。Muse 官方订阅与普通 API 计费分开，不静默切换收费路线。
2. 在隔离环境明确不装旧 provider 包，验证自研包能独立挂载；依赖解析路径和 imports 不得偷偷指回真实 profile 的旧包。保留 dsh 必需的原生服务。
3. 用合成凭据和 mock 服务验证协议、认证、流式、工具调用往返、推理档位、已声明的图片能力、上下文与输出上限、取消、超时、重试、限流、断连恢复及凭据替换。不能只做 `/models` 或一次文本回复。
4. 使用真实套餐做最小必要端到端验收，先确认其有效认证和账户；只使用无隐私测试内容，不传用户项目或历史会话。实际付费额度使用受独立门槛约束：本条条件卸载授权本身不视为无上限消费授权。未执行的项目明确保留为未验证。
5. Web 与 headless 分别完成日常路径；保留 route/model ID 和默认模型，测试历史会话继续使用所需能力。先备份和隔离验证会话迁移，不用旧版本直接打开新格式验证回退。
6. 检查卸载候选的反向依赖，备份真实 profile、锁文件、插件产物及本地补丁。先在候选 profile 停用旧插件、验证恢复；不立即删除历史证据。
7. 全部必需测试通过、独立审核放行后，按明确包名从对应 profile 卸载旧 provider 插件，保留设置、凭据和会话；只重启需要重启的服务，复核路由、模型、UI 和 key 来源。
8. 卸载后复测并记录实际移除清单、剩余基础依赖、安装包 hash 和恢复方法。测试失败则恢复原 profile/插件组合，不靠改默认模型、隐式 fallback 或放宽断言掩盖失败。

## 兼容性表述

“兼容通过”指指定 dsh 版本、插件版本、套餐/模型和测试范围内的结果。不能保证任意未来版本永久兼容；升级时重复相关验证。当前条件授权已记录，但目前无旧插件被卸载。
